看清一个进程到底在对你的文件和网络做什么。

iotap 是一个面向 macOS 和 Linux 的命令行工具。告诉它一个进程 ID 或名称，它就会把该进程的每一次读写在发生的当下报告出来：是哪个文件或远程地址，请求了多少字节、实际传了多少，这次调用花了多久，有没有失败。停下来时，它会按文件和端点汇总整个跟踪。

从上到下读，这就是一次 curl 的完整一生：

  1. 向 93.184.216.34 的 443 端口发送一个 517 字节的请求。
  2. 请求读回 16 KiB，实际收到 4 KiB。
  3. 再次请求，却发现还没有数据到达：EAGAIN。
  4. 把这 4 KiB 写入 page.html。
  5. 向终端写入 20 字节的进度信息，然后退出。

常用工具各自只能看到一角

机器上有东西在忙，你想知道到底在忙什么：某个进程正在狂啃磁盘；刚装的应用在跟一个你从没听说过的地方通信；构建慢得可疑，你怀疑是 I/O；或者某个程序总是失败，你想看看它究竟栽在哪个文件或哪条连接上。

iotap 把这些碎片拼在一起：字节数、它们属于哪个进程，以及它们去往哪个文件或端点。

各工具能看到什么、漏掉什么
工具能看到漏掉

选择要监视的对象

目标可以是进程 ID，也可以是名称。给名称时，凡是进程名、可执行文件名或第一个参数与之相同（不区分大小写）的运行中进程都会被选中，之后以该名称启动的进程也会被一并跟踪。

加上 -f，被跟踪进程启动的每一个进程也会被跟踪，不管是开始时就已在运行的，还是之后才启动的。

sudo iotap 1234                # 单个进程
sudo iotap Safari              # 所有 Safari 进程，包括新启动的
sudo iotap -f make             # make 及其启动的每个进程
sudo iotap -i wlan0 firefox    # 只看经过 wlan0 的网络 I/O
sudo iotap -q -d 10 Finder     # 10 秒后只输出汇总

一次跟踪，四种读法

事件流就是你在上面看到的那样。跟踪结束时，iotap 会做汇总。对于运行较久的进程，终端界面会实时显示同样的表格；JSON Lines 可以喂给 jq 或存成日志；录制下来的跟踪则可以稍后以上述任一形式回放，而且不需要 root。

录制

--record FILE 保存跟踪，--replay FILE 把它送回同一套处理流程，因此无论用哪种输出模式回放，得到的都和实时运行时一模一样。录制文件只含路径和地址，不含传输的数据，并且要在录制它的那个操作系统上回放。

sudo iotap --net-only --record t.iotaprec 1234
iotap --replay t.iotaprec              # 同样的输出，无需 root

它只是读取内核本来就在记录的东西

程序的每一次 read、write、open 和 connect 都是系统调用，而内核可以按要求把每一次调用随发生记录下来，连同发起调用的进程、参数和结果。iotap 读的就是这份记录。

它不附加调试器，不注入代码，也不改动被监视程序的任何东西。

在 macOS 上
这份记录来自内核跟踪设施 kdebug，也就是 Apple 的 fs_usage 所读取的同一来源。它内置于内核，无需安装任何东西。
在 Linux 上
iotap 把一个自带的小型 eBPF 程序挂到内核的系统调用跟踪点上。内核在运行前会校验它，并在 iotap 退出时将其卸载。
为什么需要 sudo
两者都是通往机器上每一个进程的窗口，所以内核只把它们交给 root。没有 root 时，iotap 会直说，并在碰任何东西之前就停下。回放录制不需要 root。
只记元数据
iotap 记录调用、描述符、字节数、延迟、路径和套接字端点。它从不读取或保存正在传输的数据：某个进程读取你的 SSH 密钥时，显示的只是对该文件的一次读取及其大小，绝不会是内容。
只看你指定的
内核只被要求记录你指定的进程的调用，加上 -f 时还包括它们启动的进程。其他的一概不记。
不留痕迹
在 macOS 上，同一时间只能有一个程序拥有 kdebug，所以 iotap 会在每一条退出路径上释放它，包括出错、收到信号和 panic。在 Linux 上，iotap 一退出，内核就会丢弃 eBPF 程序。终端界面也以同样的方式恢复终端。
一个二进制，没有守护进程
iotap 只在你运行它时运行，自己不会建立任何连接。可选的主机名解析（--resolve）走系统的解析器。
它看不到的
内存映射的文件 I/O，以及内核代进程完成的 I/O，例如页缓存回写。在 Linux 上还有通过 io_uring 或 libaio 提交的 I/O。其余的列在 README 的 Limitations 一节。

构建它，然后用 sudo 运行

iotap 用 Cargo 从源码构建。它可以在 macOS 上运行，也可以在 64 位 Arm 或 x86-64 上的 Linux 5.8 及更高版本上运行，前提是内核启用了 BPF 和系统调用跟踪点，发行版内核都满足。

构建需要 Rust 1.98.1，由 rust-toolchain.toml 指定。macOS 上还需要 Xcode Command Line Tools；Linux 上还需要 clang、make、pkg-config、一个 C 编译器，以及 libelf 和 zlib 的开发文件。

在 Debian 和 Ubuntu 上，先安装 Linux 构建所需的东西：

sudo apt install build-essential clang pkg-config \
  libelf-dev zlib1g-dev

然后构建并跟踪一个进程：

git clone https://github.com/rath/iotap.git
cd iotap
cargo build --release
sudo ./target/release/iotap curl
